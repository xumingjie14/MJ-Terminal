# 铭杰终端机 MJ Terminal

便携式个人终端：在公用/共享电脑上提供隔离浏览器 + 节点出口，不改动宿主机的系统网络设置。双击启动后守护进程在后台常驻，关闭桌面不影响连接；在系统内「设置 → 退出系统」才会完全停止。

## 下载（64 位 Windows）

到本仓库的 **Releases** 页面下载 `MJ-System-64bit.zip`，解压后运行 `MJ-System.exe` 即可，第一次运行会自动释放内置核心。本仓库为公开仓库，免登录直接下载。

## 应用内更新（v0.6 起）

程序自带 OTA：`设置 → 软件更新`。仓库是公开的，不需要令牌：守护进程会在启动时静默检查新版并预下载，在设置里点「重启并更新」即可完成升级（节点、数据、壁纸都不动）。设置里的令牌框只在仓库改回私有后才需要（且存了坏令牌会自动改走匿名请求，不会挡住更新）。构建时会同时发布 `update.json`（版本/大小/SHA-256）供程序校验更新包。

## 网站应用（v0.10 起）

常用网站可以「钉到桌面」：在「谷歌浏览器」页里添加（名字 + 网址），桌面右侧就会多一个图标（显示网站真实图标，取不到时回退为字母）。点开时以浏览器的应用模式打开——没有地址栏、没有标签页，像独立 App 一样干净，自动走节点（全局加速开着时）。快捷方式存在 EXE 旁的 `Data/apps.txt`，跟着文件夹走；删除过的默认项记在 `Data/apps-deleted.txt`，升级不会复活。预置：X、YouTube、铭杰工作站（流动性面板）、TradingView、ETF 资金流、Coinglass、Gmail、谷歌翻译、哔哩哔哩、GitHub、Vercel、ChatGPT、Gemini、Muse、TikTok。

## 桌面交互（v0.12 起）

桌面图标（系统应用、网站应用、文件夹）都可以自由拖动摆放（单击选中、双击打开，跟真实桌面一致），位置保存在 `Data/layout.json`，跟着文件夹走。在桌面空白处点右键有菜单：**新建文件夹**、**刷新**、**个性化**（跳到设置换壁纸）。

**拖拽逻辑（v0.31 起，按 macOS Launchpad 复刻）**：拿起图标时它放大到约 1.08 倍、半透明带阴影，原位留一个虚线空位；拖动过程中其他图标实时滑动让位，落点在松手前就一目了然，松手时被拖图标动画滑入空位，不再有松手跳变。把网站图标拖到文件夹上，文件夹立刻「开花」响应，松手即放入（文件夹不改名，缩略图按内容刷新）；把网站图标拖到另一个网站图标上**停留约 0.6 秒**，目标开花表示已就绪，松手即把两者叠成一个新文件夹并立刻打开它、名字处于可编辑状态（直接打字回车改名）；快速拖过只是路过排序，不会误建文件夹。拖动中按 Esc 取消，一切滑回原位、不保存。文件夹打开形态改为 Launchpad 式：桌面变暗模糊，中央展开面板，顶部文件夹名点一下就地改名（回车/失焦提交），点面板外关闭，没有按钮条；面板内拖动同样实时让位排序；把图标拖出面板就落回桌面对应位置，面板随即关闭；文件夹被拖空自动解散，只剩一个时保留。（v0.35）桌面布局改为单一顺序源：四类图标与文件夹共用一份有序名单依次落格，渲染与拖拽共用同一顺序、拖动只动新旧位置之间的图标，旧版本存下的重叠/错位布局会在载入时按原阅读顺序自动规整，控制台（模块「布局」）会留一条记录。

## 台前调度（v0.15 起）

「设置 → 台前调度」或菜单栏的 ▦ 开关：开启后桌面只显示当前应用，其他打开的应用以实时缩略图排在左侧，点缩略图切换；关闭当前应用会自动顶上一个。

## 窗口统一（v0.18 起）

从桌面打开的网站应用仍是独立的浏览器窗口，但守护进程会把它们登记在册：台前调度开启时，左侧缩略图下方会多出一组「外部应用」，点任意一张卡片就把那个真实窗口切到最前，不必再去 Windows 任务栏里翻。同时桌面窗口与这些应用窗口共用同一个应用身份标记，Windows 任务栏会尽量把它们合并成一颗按钮（是否合并取决于宿主机的任务栏设置，属尽力而为）。v0.20 起，这些外部应用从桌面打开时会自动落在桌面范围内（菜单栏与 Dock 不被遮挡），落位只在打开时发生一次，之后可自由拖动与最大化。v0.21 按真机反馈把落位尺寸调小：打开的窗口约占桌面六成宽、八成半高，四周露出桌面，整个系统在后面也看得见。v0.23 起增加小窗手机宽：当终端窗口没有最大化、或宽度不足 1200 时，从终端新打开的网站应用以约 400px 的手机宽度落位（高度与竖直位置不变），多数网站会按这个宽度自动呈现手机版排版；桌面最大化且够宽时仍按 v0.21 的比例落位。落位仍只在打开时发生一次。

**覆盖范围补全（v0.31 起）**：① 应用商店装的便携应用（Telegram、VLC 等）启动后同样认领主窗口并登记——统一身份标记、一次性落位、进台前调度列表，认领按「该程序的新窗口」找，不死认启动进程（便携应用常自拉子进程）。② 浏览器自己新开的窗口也会被自动认领进台前调度：守护进程每约 2 秒巡查一次已登记浏览器窗口所属的进程，把同进程新出现的浏览器主窗口（类名 Chrome_WidgetWin_1 / MozillaWindowClass、可见、无属主、尺寸不小于 200×100）登记进来——网页弹窗、Ctrl+N 新窗口、拖出成窗的标签、独立的开发者工具窗口都在内。认领只按 PID 匹配：隔离浏览器是独立进程，与宿主机自己的 Chrome 天然不是同一个 PID，绝不会误认宿主窗口；桌面外壳（Edge）也不在巡查范围内。自动认领的窗口**只登记可切换，绝不落位、不抢焦点**（弹窗有它自己的位置逻辑）。巡查开关在「设置 → 桌面与 Dock → 浏览器新窗口自动纳入台前调度」（默认开，存 `Data/settings.json` 的 `stageAutoClaimBrowser`，关掉后已登记的窗口不受影响）；认领事件记入控制台（模块 `winmgr`）。

**全覆盖重构（v0.36 起）**：v0.31 的巡查只盯已登记窗口的进程，真机使用中发现漏口：Firefox 从未在启动时登记、浏览器崩溃重启后换了进程、应用经启动器转生、浏览器把文件交给外部程序打开——窗口落在宿主任务栏上，台前调度里却找不到。v0.36 改为全盘点判定：巡查每约 2 秒枚举全部顶层窗口与全部进程，按三条硬证据判定归属——① 进程命令行带着隔离浏览器档案路径（隔离 Chrome 的 `Data/ChromeProfile`、Firefox 档案目录，整段精确匹配，宿主自己的浏览器天然没有）；② 程序文件位于终端文件夹内（应用商店应用、组件、导入的可执行文件）；③ 进程是守护进程亲手启动的进程树的后代（浏览器点开 PDF 跳到 SumatraPDF 这类转手也算）。命中任一即登记进台前调度，浏览器弹窗每个都是独立条目、标题随页面标题刷新；开关此后只管浏览器自动认领这一类，商店应用等终端程序的新窗口属台前调度本职、不受其影响。守护进程另记着自己启动过的每个进程（启动账本）；窗口刚出现还没标题时宽限一轮，仍无标题则先行登记并在控制台（模块 `winmgr`）留一条自检警告，漏认领不再靠用户发现。

**开窗礼仪（v0.37 起）**：窗口进名单的那一刻起守终端的规矩——① **出生落位一视同仁**：巡查认领的窗口与守护进程亲手打开的窗口同等待遇，第一次登记时按同一套落位摆进桌面区域（出生即最大化的先还原再摆；有属主的对话框不摆），一生只摆这一次；② **桌面垫背**：你正在终端里操作时（前台是桌面或任一已登记窗口，或守护进程刚从桌面打开它），新窗口出生时桌面会被垫到它正下方，看上去就是在自己的系统里开应用；你忙宿主应用时新窗口只悄悄登记、绝不抢屏；③ **最小化联动**：桌面最小化，已登记且正显示的窗口整套跟着隐藏，桌面自己照常留在宿主任务栏里，桌面恢复时整套按原样回来（你单独最小化的窗口不碰）；④ **关闭退托盘**：关掉桌面视图，整套窗口隐藏且不留任务栏按钮，守护进程在宿主系统托盘放一个图标（多半落在 ^ 隐藏区），点图标或照旧双击 EXE 即可整套恢复，托盘右键可「打开桌面 / 退出系统」。整套藏着期间新生的窗口直接跟随隐藏、不会单独亮在宿主桌面上；台前调度里点某个窗口会先整套恢复再提它。**硬安全线**：任何退出路径（设置退出 / 托盘退出 / 空闲自动退 / 更新交接）都先把整套窗口恢复可见再退，绝不把藏起来的窗口留在机器上。三个开关在「设置 → 桌面与 Dock → 开窗礼仪」（`winPlaceOnClaim` / `winHideOnMinimize` / `winCloseToTray`，默认全开；垫背跟随落位开关），全程记入控制台（模块 `winmgr`）。注意本版**不做**任务栏按钮逐个隐身：平时每个窗口仍在宿主任务栏有自己的按钮，只有整套联动隐藏时才不在。

## SSH 远程终端（v0.19 起）

桌面内置「SSH」应用：在系统内窗口里开终端（xterm），守护进程直连服务器。连接列表、私钥文件、服务器指纹（known_hosts）都存在 EXE 旁的 `Data/ssh/`，跟着文件夹走；密码和私钥口令只在连接时输入、**不落盘**。第一次连某台服务器会记下它的指纹，之后每次连接都校验，对不上直接拦住，不可绕过。每条连接可单独开「走节点连接」（默认直连）。同一窗口下方带 SFTP 文件面板，共用终端连接浏览、上传、下载、建目录、删除远程文件，不用再输一次密码。

## 服务器监控（v0.26 起）

桌面内置「服务器」应用（对标哪吒监控）：借用 SSH 应用里已保存的连接**无探针采样**——守护进程每轮用一条组合命令读服务器的 `/proc`、磁盘与服务状态，服务器上不用装任何东西。总览是卡片墙（在线状态、CPU、内存、实时上下行、本月流量、运行时间）；单机详情有 CPU/内存/磁盘/负载、进出流量实时曲线与历史（1 小时 / 24 小时 / 7 天）、今日/本月/累计流量统计与月配额进度条、服务状态（sing-box / xray / hysteria / nginx / docker）、进程占用 Top、监听端口，以及一行命令行（常用命令一键执行 + 自由输入，命令原文不进日志）。每台服务器有独立监控设置：后台采样开关（开后关着面板也每分钟采样）、月流量配额、磁盘/流量/服务停止告警——告警与采样事件全部进「控制台」（模块 `servermon`）。历史与流量统计存在 EXE 旁 `Data/servermon/`，保留 30 天；流量是终端机按采样累计的口径（守护进程没运行时不计），与服务器商账单会有小出入。自动采样只适用于密钥连接（无口令）或已在 SSH 应用里打开的终端连接；密码/带口令密钥的连接可在详情里输一次密码手动采样，凭据不落盘。

本版同时包含下载加固：更新包与 Firefox 组件下载前会先尝试把节点拉起来再走节点下载（`ensureCoreForDownload`），下载状态文案明示「走节点 / 直连」，不再静默直连。

**服务器采集（v0.27 起，可选）**：详情页可一键把一个小采集脚本装到服务器上（写入 `~/.mjmon/collect.sh`，systemd 用户定时器 + linger 自启校验，未确认时自动加 crontab 双保险，不需要 root）。它每分钟把 CPU/内存/网卡计数记一条到服务器本地的按天文件（留 35 天），**采集本身不联网、不产生流量**；面板开着时每 5 分钟经 SSH 把缺失的样本拉回，合并进本地历史曲线，并按样本日期把流量补记进今日/本月/累计——电脑关机、退出终端机的时段不再断档。首次同步拉增量之前的全部（整月约 4 MB 文本），之后每次只拉新增（通常几 KB）。同步与安装事件都进控制台（模块 `servermon`）；卸载会删掉定时器与服务器上的 `~/.mjmon`。

## 设置（v0.30 重构）

「设置」应用按 macOS 系统设置的语法重做：左侧搜索框 + 彩色分类清单，右侧分组列表（分组标题 + 说明行 + 控件右对齐），分类为外观 / 桌面与 Dock / 节点与网络 / 浏览器 / 组件 / 存储空间 / 安全与隐私（v0.33 启用，见「远程协助」一节）/ 通用 / 关于 / 软件更新，顶部是系统卡（铭杰终端机 + 当前版本，点进软件更新页，原有更新 UI 与接口整体迁入，行为不变）。偏好统一存 `Data/settings.json`，跟着文件夹走（守护进程接口 `GET/POST /api/settings`，每次变更进控制台，模块 `settings`）：壁纸预设选择与台前调度开关从桌面视图的 localStorage 迁入（老用户首次打开新版时自动搬运一次）；空闲自动退出时长可配（15/30/60 分钟或不自动，默认 30，守护进程每分钟读取当前值）；手机宽模式开关、触发宽度与落位宽度可配（默认开、1200/400，winmgr 每次落位读当前值）；v0.31 在「桌面与 Dock」加了「浏览器新窗口自动纳入台前调度」开关（`stageAutoClaimBrowser`，默认开，winmgr 巡查每轮读当前值）。**存储空间**页盘点整个文件夹（程序本体 / Chrome 档案 / Firefox 档案 / 小龙虾 / 商店应用 / 日志 / 壁纸 / 其他，接口 `GET /api/storage/usage`，带统计耗时），并可一键清理纯缓存（接口 `POST /api/storage/cleanup`，模块 `storage`）：只清 Chrome 档案下的 Cache / Code Cache / GPUCache 等缓存目录、Firefox 档案的 cache2、更新暂存残留与核心旧日志，绝不碰 Cookies / 书签 / 历史 / 任何配置；隔离 Chrome 或 Firefox 正在运行时拒绝执行并说明原因。隔离 Chrome 的磁盘缓存上限也在浏览器页设置（默认 200 MB，0 = 不限制；启动时以 `--disk-cache-size` 注入并在日志中注明）。

## 文件导入（v0.32 起）

宿主电脑的文件可以递进终端桌面，但永远**由用户亲手递**，守护进程不翻宿主的任何目录：把文件**拖到桌面**上松手、用桌面右键菜单的「从电脑导入文件…」走系统选文件窗口、或在宿主那边复制后到桌面 **Ctrl+V 粘贴**——三条通道共用一个流式上传接口（`POST /api/files/import`，单文件上限 500 MB，不整文件读进内存），副本落在 EXE 旁的 `Data/files/`，**宿主原文件一个字不碰**；同名不覆盖，自动改名 `名字 (2).扩展名`。

导入的文件是桌面上的一种新图标，与应用图标**混排**在同一套自由布局里（位置记在 `Data/layout.json` 的 `file:<文件名>` 条目下，老布局无损加载），参加 v0.31 的拖拽排序与实时让位，但**不能拖进文件夹、不能叠建夹**（文件夹仍只装网站应用）。图片（jpg/png/gif）显示守护进程生成的真实缩略图（标准库解码、等比缩到约 128px、缓存在 `Data/files/.thumbs`，统计占用时计入文件组；webp/bmp 标准库解不了，用类型图标兜底），其余按类型给 macOS 风类型图标 + 扩展名角标。文件图标右键菜单有打开 / 重命名 / 导出到电脑 / 删除：改名不许带路径、不许与现有文件重名；删的是终端里的副本，确认框明示电脑上的原文件不受影响；「导出到电脑」就是以该文件触发一次桌面视图下载、落到宿主的下载文件夹，菜单文案如实标注，不含糊。

**双击打开全在系统内解决**，从不默默调用宿主默认程序：PDF 优先用应用商店的 SumatraPDF（装了就走它的启动路径并登记台前调度），没装则用隔离 Chrome 打开 `file://` 地址；图片走系统内「图片」应用（适应窗口/100% 切换、同目录图片按钮或键盘左右切换）；纯文本走「文本」应用（只读、等宽、自动换行开关、只读前 2 MB）；CSV 走「表格」应用（细线表格、前 200 行 × 前 50 列，超出注明截断；首行作表头）；DOCX 由守护进程抽文字（标准库解 zip 取 `word/document.xml` 去标签成段落）复用「文本」应用预览，标题注明仅文字；XLSX/PPTX 给两个诚实选项（传到网页版办公腾讯文档里打开，或导出到电脑用本机软件），不假装能本地编辑；ZIP 双击解压到 `Data/files/<同名文件夹>/`（先全包预检：任一路径逃逸或解压总量超 2 GB 整包拒绝，不静默跳条目），桌面出文件夹图标，双击在列表小窗里看第一层内容并逐个按同规则打开。**可执行文件（exe/bat/cmd/msi）双击先弹确认框**，写清文件名与「将在这台电脑上运行」，确认后才由守护进程启动（.exe 顺带登记台前调度并落位；.bat/.cmd 经 cmd、.msi 经 msiexec 承载，窗口不登记），取消什么都不发生，每次确认启动都记日志。查看器都是系统内窗口（进台前调度），但不占桌面图标位与 Dock，从文件双击唤起。

三件套集成照旧：全部事件进控制台（模块 `files`）；设置「存储空间」多一组「导入的文件」（`Data/files` 总量）；设置「桌面与 Dock」有开关「在桌面显示导入的文件」（`filesOnDesktop`，默认开；关掉只隐藏图标，文件与导入通道不受影响）。

## 远程协助（v0.33 起）

被主人**配对批准**的操作者（设计上是主人自己的 AI 助手们，不写死任何身份）可以经主人的私有 Tailscale 网络远程读取终端状态与日志、做协助操作——报 bug 不必再导出诊断包手动搬运。实现在 `remote.go`（操作者存储/配对/鉴权/受限 mux/脱敏）+ `remote_tsnet.go`（tsnet 后端，仅 windows/amd64 与 linux/amd64；其余平台 `remote_stub.go` 报不支持，含官方不支持的 windows/386）。

- **组网**：Tailscale 客户端库（tsnet）直接编进守护进程，纯用户态组网——不装软件、不要驱动、不要管理员，节点状态在 `Data/tsnet` 跟着文件夹走，设备名 `mj-terminal`。设置键 `remoteEnabled` 默认**关**：关时组网根本不启动，攻击面与 v0.32 完全一致；守护进程启动时若开着会自动拉起，退出系统时正常关闭。
- **入口隔离**：远程走一个只绑 tailnet 的独立监听（:18790）与一套独立 mux，与本机 127.0.0.1 的接口物理隔离，白名单之外的路径一律 404。每条请求过同一条鉴权链：WhoIs 查来源节点身份 → 已配对操作者名单比对 → 档位门 → **逐条记控制台**（模块 `remote`，含操作者名与放行/拒绝原因）。
- **配对**：未配对节点来敲门会被记成「待配对」，带一个由其节点公钥派生的 6 位配对码；主人在「设置 → 安全与隐私」把配对码告诉对方带外核对、一致才点批准（名字可自定，新配对默认只读档）。操作者名单存 `Data/remote.json`，每人一条、可单独改档/撤销；「断开并清除配对」一键清名单并关总开关。配对/改档/撤销/开关本身**只许本机 UI 操作**，远程改设置的接口若请求体里出现 `remoteEnabled` 整体拒绝。
- **档位**：只读档可看自描述端点 `/api/remote/capabilities`（给接入的 AI 冷启动读：版本、端点清单与各自所需档位、自己的身份）、组网状态、脱敏诊断状态与远程诊断包（`mj.log` + 脱敏 `status.json`）、控制台日志、系统/设置/存储/节点（仅名称/类型/服务器/端口）/加速/外部窗口/Firefox 与小龙虾状态（令牌只给 `hasToken` + 掩码）、服务器监控总览（不含密钥文件名），以及**只查不下**的检查更新。协助档追加可逆写操作：白名单内改设置、节点核心启停、加速开关、小龙虾启停、更新下载与应用。
- **红线（任何档位都不存在这些端点）**：文件内容与全部文件接口、SSH 私钥与密码、节点分享链接与订阅地址、小龙虾令牌原文、更新令牌、退出系统、应用安装/卸载、SSH 连接与终端、小龙虾配置向导、远程协助自身的开关与配对管理。凡与本机共用响应体的端点都先过脱敏 shaping（白名单逐键构造）再出门。
- **可见性**：开启时桌面菜单栏常驻「远程协助中」标记（最近 60 秒有远程请求时加重为绿色），主人在设置页随时可关、可撤销任何人。
- **登录页打开方式（v0.34 修正）**：「打开登录页」不再用外链跳宿主默认浏览器，改由本机端点 `POST /api/remote/openlogin` 把守护进程自己持有的 AuthURL 交给终端的隔离浏览器打开（经节点与否沿用网站应用的既有规则）；AuthURL 不从请求传入、也不写进日志（按秘密处理）。该端点只注册在本机 mux，远程 mux 上不存在。同一版顺带收紧了通用链接打开 `/api/open` 的 URL 分支：系统内点开的链接一律先进隔离浏览器（加速开走节点、关则直连），只有隔离浏览器根本起不来时才降级宿主默认浏览器并记一条 warn 日志。

## 调试控制台（v0.22 起）

桌面内置「控制台」应用（macOS 控制台风）：系统运行状态（版本、核心是否运行、节点是否已连、运行时长、外部窗口与 SSH 连接数）、各接口报错和全部模块日志集中在一处实时看，可按级别/模块过滤、全文搜索；点「复制诊断摘要」把状态和最近报错拼成一段文本进剪贴板，点「导出日志」下载诊断包（`mj-diag-*.zip`：日志 + 状态快照 + sing-box 日志）。日志同时落在 EXE 旁的 `Data/logs/mj.log`（单文件 2 MB 自动轮转，留 3 个）。v0.30 起，守护进程启动时会把 `mj.log`（不足时连同 `mj.log.1`）最后至多 1000 条记录回填进控制台缓冲，退出重进也能看到上一次会话的记录，不再是一片空白（回填条数会记一条 `diag` 模块日志）。

## 控制台与日志约定

给后续开发的硬性约定（v0.22 起执行）：

- **新功能必须接入统一日志中枢**：守护进程里的统一入口是 `diag.go` 的 `logf(module, level, format, args...)`。关键事件（启动/停止/连接成败/任务完成）和全部错误都要记；级别用 `info` / `warn` / `error`；模块名用现成这套：`system`、`core`、`node`、`browser`、`winmgr`、`ssh`、`update`、`firefox`、`apps`（v0.24 登记，应用商店）、`openclaw`（v0.25 登记，小龙虾组件）、`settings`（v0.30 登记，统一设置）、`storage`（v0.30 登记，存储盘点与清理）、`files`（v0.32 登记，文件导入）、`remote`（v0.33 登记，远程协助：组网、配对与每一条远程请求）、`api`——新模块先在本节登记名字再用，不要各起一套。
- 接口层已有自动捕获：非 2xx 的接口响应由中间件自动记进中枢（方法、路径、状态码、简短错误）。但 handler 内部以 HTTP 200 + `{"error": ...}` 形式返回的失败中间件看不见，必须在失败点自己 `logf` 一条。
- **脱敏红线（任何情况下不许破）**：密码、私钥内容与私钥口令、更新令牌、完整节点分享链接、订阅地址的敏感部分，一律不得写进日志。SSH 只记目标主机与结果；节点只记名字/类型/服务器:端口；订阅只记域名。
- sing-box 自己的输出仍在 `core/sing-box.log`，与中枢日志分开；核心的启停与报错摘要会同步进中枢，控制台里看摘要、导出包里两份都有。
- 用户排查路径：打开「控制台」看红色报错 → 点「导出日志」拿到 `mj-diag-*.zip` 诊断包发出来定位问题。

## 应用商店（v0.24 起）

桌面内置「应用商店」：免安装的**便携应用**从官方源直下、装进 EXE 旁的 `Data/apps/<应用>/`，程序与数据都跟着文件夹走，宿主电脑不留东西；装好后桌面上会出现图标，双击启动（窗口是应用自己的原生窗口）。下载走守护进程的节点加速通道（与 Firefox 组件同一条路），装完在商店里可打开/卸载；**卸载 = 程序与数据一并全删**（便携应用的数据就在程序文件夹里），点卸载时会二次确认并明示这一点。

上架规矩（硬性）：

- **只收官方便携 / 官方绿色包**：下载地址必须是厂商官方源（官网、厂商官方仓库 Release、厂商官方 CDN）；第三方重打包、镜像站、下载站的包一律不收。
- **校验钉死**：目录里每个应用钉死版本号、体积与 SHA-256，下载后先验大小再验哈希，**对不上立即删包拒绝安装**。
- **验过才上架**：上架前必须把官方包真下载一遍，实测体积与 SHA-256，并确认解压后的启动程序路径真实存在；大包也要下全验完，没验完的不进目录。
- **目录可远程更新**：应用目录是仓库根目录的 `apps.json`，守护进程优先拉仓库 `main` 上的最新版（拉不到回退到程序内置副本），所以往商店加应用只需改 `apps.json` 并推仓库，不用发新版程序。
- 每个应用的本地状态记在 `Data/apps/apps.json`；商店的下载/校验失败/安装/启动/卸载都按日志约定记进控制台（模块 `apps`）。

首批货架（2026-10-27 逐个实测）：Telegram 7.3.3（官方便携）、SumatraPDF 3.6.1（官方便携）、Notepad++ 8.9.8.1（官方便携）、VLC 3.0.24（官方绿色包）、Everything 1.4.1.1028（官方便携）、KeePassXC 2.8.0（官方绿色包，哈希与官方 DIGEST 文件核对一致）、ShareX 21.0.0（官方便携）。

## 小龙虾组件（v0.25 起）

桌面内置「小龙虾」应用：把 AI 助手 OpenClaw 做成**按需下载的便携组件**（与 Firefox 组件同一套路：Release 上的 `MJ-OpenClaw.zip` + `openclaw.json` 清单，体积与 SHA-256 钉死，校验不过拒绝安装；下载走节点加速通道）。组件装在 EXE 旁的 `Data/openclaw/`，布局为 `runtime/`（便携 Node）、`app/`（OpenClaw 本体）、`state/`（配置/SQLite/日志/工作区）、`tmp/`、`appdata/`——压缩包只含 runtime 与 app，状态由守护进程在首次启动时在本机建好，所以整夹拷到另一台电脑也能用。

托管纪律（2026-10-27 便携验证定版，改动前先读验证报告）：

- **先写配置再启进程**：首次启动前守护进程直接写 `state/openclaw.json`——`gateway.mode=local`（缺它网关拒绝启动）、`logging.file` 指向组件内绝对路径（该路径是绝对的，**每次启动前都核对，组件被挪过位置就改写**，且直接改 JSON 不用 openclaw CLI 改）、`gateway.port=18789`。网关自身不保存令牌（无令牌时它只生成一次性临时令牌，谁都读不回来），所以 provisioning 同时生成一个随机令牌以 `gateway.auth`（mode=token）写入配置，页面从配置读回展示/复制；**令牌与任何 API Key 永不进日志**（脱敏红线同样适用）。
- **只用前台托管**：守护进程以 `gateway run --port 18789 --bind loopback` 拉起网关并托管（Windows 上进程入 Job Object、关句柄即整树回收；其他平台用进程组），**绝不用 `gateway install`**（Windows 上那是注册计划任务，违背免安装原则）。网关意外退出记入中枢并在页面标明原因；v0.29 起可开「崩溃后自动重启」（退避 5/20/60 秒，10 分钟内最多 3 次，超限停手并报错，多半是配置或 Key 问题）。
- **出站可走节点**：页面开关「模型流量走本地节点」默认开；开且核心在跑（或能按已保存节点拉起）时给网关子进程注入 `HTTP(S)_PROXY=127.0.0.1:2080`；拉不起则直连启动并在页面与日志中明示「本次直连」，不静默。网关的 stdout/stderr 进组件内 `state/logs/gateway-process.log`，中枢只记生命周期事件（模块 `openclaw`）。
- **已知残留与清理**：网关的 state-owner 锁目录在 Windows 上是源码写死的 `%LOCALAPPDATA%\OpenClaw`（不读环境变量、无开关；另有读环境变量的路径已由进程级 APPDATA/LOCALAPPDATA 重定向挡进组件 `appdata/`）。守护进程在首次启动前记录基线（组件内 `.mj-lock-baseline.json`：该目录原本是否存在），停止时在进程全停、端口释放后，**仅当基线为原本不存在时才删除它**，清理结果记入日志。
- **退出联动**：设置→退出系统、空闲自动退出、OTA 交接退出都会先停网关再退守护进程；小龙虾在跑时空闲自动退出不触发。
- **定位**：约 630 MB 体积、约 1 GB 内存的重型组件，且权限高（能操作电脑、收发消息），只建议在自己的电脑上用；消息渠道仍由用户在小龙虾自己的控制台里配。

**页面升级（v0.29）**：状态卡实时显示运行状态、运行时长、进程树内存（Windows 用 Toolhelp 快照 + GetProcessMemoryInfo，其他平台读 /proc）、磁盘占用；设置成分组开关（模型流量走节点 / 随终端机自启 / 崩溃后自动重启，存组件内 `mj-prefs.json`）。**配置向导**：选厂商（OpenAI / Anthropic / DeepSeek / 自定义 OpenAI 兼容接口）、填 API Key、选默认模型——保存走 OpenClaw 自己的 CLI（`config set` / `models set`，写前它自动备份配置、且热生效不用重启网关；自定义厂商按 schema 要求整段声明含 models），守护进程只负责驱动 CLI 与读回状态（只显示 Key 尾号）；「测试连接」用填的或已存的 Key 请求厂商 `/models`（走下载加速通道，节点在跑时经节点）。Key 只在页面→守护进程→组件配置之间流转，永不进日志，CLI 报错回显前先脱敏。页面内嵌网关日志尾巴；数据可一键导出（`state/` 打包 zip，不含日志）与导入（导入前现有 `state/` 改名备份，再用 ocProvision 整理路径）。

构建时 CI 在 windows-latest 上用便携 Node v24.22.1（PATH 钉死 + `--scripts-prepend-node-path=true` + 版本护栏，验证 run #1 的教训）以 npm 本地 prefix 方式组装 OpenClaw 2026.10.8，产物即组件包与清单，随 Release 一起发布。

## Firefox 组件与谷歌同步（v0.16 起）

桌面上有两个浏览器，分工不同：

- **Firefox（登录可搬家）**：按需下载的独立组件（约 140 MB，包不进主程序），在「Firefox」页点下载即可。它用自己的档案（`Data/FirefoxProfile`），登录、Cookie、历史都锁在档案里——把文件夹带到另一台电脑，登录状态样回来。支持走节点/直连打开与「应用化打开」（隐藏标签栏和地址栏，冷启动时生效）。建议在 Firefox 里给档案设主密码。
- **谷歌浏览器（Chrome）**：登录被那台电脑的 Windows 账户锁着、搬不走；补救是「谷歌浏览器」页里的**谷歌云同步**入口——开启同步后换电脑登一次谷歌，密码、书签、历史同步回来。

构建时 CI 会另外发布组件包 `MJ-Firefox.zip` 与校验清单 `firefox.json`（Firefox ESR 中文版，官方安装包解开后便携化打包，仅用 policies.json 关掉它自己的自动更新，版本由我们发布节奏控制）。
